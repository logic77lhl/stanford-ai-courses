# Playbook Library · 可复现的「策展型站点」模板

> 一组可以直接交给 AI 的项目规格书。每个模板都对应一种「目录 + 详情页 + 关系/时间线」的策展型站点。
>
> 不局限于课程，也不局限于 AI。课程、论文、工具、会议、数据集、学者、书单、公司、法规、城市指南，共用同一套骨架。

---

## 1. 为什么这些项目能复用同一套骨架

它们看起来完全不同，但底层结构高度一致：

```text
一批条目（Item）
   ├── 每个条目有若干属性（Facets）
   ├── 条目之间有relations（先修、引用、替代、管辖）
   ├── 条目关联外部artifacts（课件、代码、PDF、官网）
   └── 需要标注来源与新鲜度（Sources / Freshness）
        │
        ▼
目录页（Index） + 详情页（Detail） + 关系页（Graph/Timeline/Compare）
        │
        ▼
校验（数量、链接、字段完整性、时间敏感字段）
```

真正变化的是：**字段、数据源、排序规则、时间敏感程度**。所以不需要为每个领域重写一套系统，只需要换一份「领域配置」。

## 3. 所有模板共用的 7 个阶段

| Phase | 产物 | 验收 |
|---|---|---|
| 0 立项 | Brief + 分类 + 收录标准 | 每类 3 个代表条目 |
| 1 目录 | `catalog.json` | 条目数、字段完整率 |
| 2 策展 | `items/*.json` | 必填字段齐全、摘要可读 |
| 3 文档 | `items/*.md` | 固定小节、链接可点 |
| 4 站点 | `docs/*.html` | 页面数 = 条目数 |
| 5 增强 | 关系图 / 时间线 / 对比 / 外部资源 | 每条关系有来源 |
| 6 校验 | `check.py` + CI | `errors: 0` |
| 7 部署 | Pages/Vercel | 线上冒烟通过 |

细节见 [00-universal-skeleton.md](00-universal-skeleton.md)。

## 4. 统一数据模型

无论哪个领域，条目都可以归一成这一份结构：

```json
{
  "id": "CS 229",
  "slug": "cs229-machine-learning",
  "name": "机器学习",
  "name_en": "Machine Learning",
  "category": "基础核心",
  "summary": "一句话说清它是什么、为什么值得看。",
  "facets": {
    "difficulty": 4,
    "cost": "free",
    "status": "active",
    "year": 2026
  },
  "tags": ["ML", "监督学习"],
  "links": [
    { "label": "官网", "url": "https://...", "type": "official" }
  ],
  "relations": [
    { "type": "prereq", "target": "CS 230", "note": "建议先学" }
  ],
  "artifacts": [
    { "type": "slides", "label": "Lecture 1", "url": "https://...", "access": "public" }
  ],
  "sources": [
    { "url": "https://...", "retrieved_at": "2026-10-31" }
  ],
  "freshness": {
    "checked_at": "2026-10-31",
    "volatile": ["deadline", "price", "status"]
  }
}
```

字段名可以按领域调整，但**这 9 个维度不要少**：身份、分类、摘要、可比较属性、标签、链接、关系、外部产物、来源与新鲜度。

## 6. 三条通用铁律

1. **目录与策展分离**  
   抓取结果放 `catalog.json`，人工判断放 `items/*.json`。抓取可以重跑，策展不能被覆盖。

2. **不伪造链接**  
   找不到官方资源就留官方入口，写「以官网为准」；第三方资源必须标注风险与最后核验日期。

3. **数量与链接必须硬校验**  
   `check.py` 要校验页面数、条目数、站内链接、必填字段。只检查「构建成功」等于没检查。

## 7. 怎么用这套模板

### 方式 A：直接开工

1. 选一个模板（例如 `02-paper-map.md`）。
2. 填模板里的 Brief 片段。
3. 把 `MASTER-PROMPT.md` + 模板 + Brief 一起发给 AI。
4. 要求它先做 Phase 0–2，验收后再继续。

### 方式 B：先做 MVP

每个模板末尾都有「30 分钟 MVP」：只做 20–50 个条目、3 个页面、无关系图。先看效果，再决定是否扩。

### 方式 C：组合

先读 `00-universal-skeleton.md`，把多个模板的字段合并成自己的 schema，再让 AI 按统一骨架实现。

## 8. 模板之外的四个问题

在动手前，先回答：

1. **谁会来第二次？** 如果没人复访，说明缺「变化」：新课、新论文、新 deadline、新价格。
2. **哪些字段半年后会错？** 这些字段必须带 `checked_at`，并进入巡检。
3. **排序规则能否解释？** 如果只能用「感觉」，就写成 rubric，别假装客观。
4. **最小可信版本是什么？** 通常不是 500 条，而是 50 条字段完整、来源可靠的条目。

## 11. 不建议用这套骨架的项目

- 实时行情/天气：需要流式数据与推送。
- 社交/评论社区：需要账号、审核、数据库。
- 在线代码运行：需要沙箱与后端。
- 电商交易：需要支付、库存、订单。
- 纯内容博客：用静态博客框架更省事。

这些不是不能做，而是「静态数据 + 生成页面」的收益不够高。
